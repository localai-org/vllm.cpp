# Original-format dense shard seam

Issue: `ISSUE-LOCAL-01M63VRMM7HCJJ1MN1QSEVT88E`.
Spec-first commit: `8f4ef1005`.

The shared dense representation now accepts original q/k/v and gate/up shards.
`vt::MergedGemmDense` runs registered `MatmulBT` operators without converting the
weight dtype. The attention block consumes three contiguous products. The MLP
routes its two products and split activation through `MlpGateUpMethodBase`.
Existing empty-parts model paths retain their previous operations.

The new tests initially fail compilation because the shared realization and
method do not exist. After implementation, the focused host gate passes 2 cases
and 8 assertions. The complete existing linear-method suite passes 10 cases and
96 assertions. Production `merged_gemm.cpp`, `qwen3.cpp`, and the test compile
with the existing Release compilation commands. A scratch archive replaces only
the two production objects; no reviewed worktree or build cache is mutated.
Commands are generated by `/tmp/quant-parts-compile.py` from
`/tmp/lumen-build-legacy/compile_commands.json`, with the source root changed to
this worktree. The focused binary runs with `--test-case=dense*`.

Removing the final contraction makes both new cases fail. Swapping the split
SwiGLU operands makes the MLP case fail. Production sources remain unchanged
during mutations. The restored complete host gate passes.

Checkpoint header inspection measures original tensor bytes, not peak device
memory. TinyLlama uses 636.18 MiB packed, versus 1488.76 MiB with QKV and gate/up
expanded to BF16. SmolLM2 uses 98.87 MiB packed, versus 185.52 MiB expanded. These
figures exclude allocator, KV cache, scratch, and non-tensor GGUF metadata.

This slice is not complete model acceptance. The Llama GGUF adapter must populate
these fields through the public loader in the same campaign. Its owning row is
`BACKEND-CUDA-SM061`, and the issue above owns the wiring. The real-model public
entry-point gate and its production-call mutation remain pending that adapter.
The existing CUDA split SwiGLU kernel also needs the legacy input-width rounding
fix before GPU parity can be claimed. No throughput claim is made here.
