Four independent blockers follow, and the NVFP4 half is the half closest to working. On the GGUF side the Q4_K_M file confirms #821's counts (v3, `qwen35`, 866 tensors, Q4_K/Q5_K/Q6_K/Q8_0/F32, data end == 17,106,775,008 == file size) and adds two facts it did not have: `block_count = 65` with `nextn_predict_layers = 1`, so block 64 is the MTP DRAFTER and a loader reading `block_count` as decoder depth builds the wrong graph, and `padding_token_id = 248055` against 248044 in the same model's BF16 GGUF and `null` in the official config. The `mmproj-BF16.gguf` ships BOTH halves of the temporal patch embedding (`v.patch_embd.weight` + `v.patch_embd.weight.1`), the exact thing MuseGlimmer's lacks, so it is loadable and that refusal is not precedent against it. Ten of the sixteen declared tests need no GPU and no lease.
